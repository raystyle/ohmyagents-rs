## 关键裁决

- 绑定链完整口径：服务 label 探测不重开 → 会话 reuse_only → 窗格 manifest pane_id → 死路 reconcile 重开 → 强制 respawn 单路。「初始检测互斥，操作绑定已开实例」全程成立。
- 资源释放的单位是内容指纹不是版本号；清理（旧指纹）必须在复用与重释放两条路径都做（单测边界用例抓获）。
- 排查 rmux 进程按 `--__internal-daemon` 参数找，不按进程名。
- 验收标 `[实证]` 前必须核对**命令面**真消费了该路径——端点存在不等于命令接线（P0025 首版 stop 只有 taskkill、手册却写协议化，就是部件验证过、链路没验证）。
- Job Object 宿主环境里一切 `.output()` 式子进程等待都是雷（tasklist 死锁），探活优先 FFI。
- catalog 出厂锚是 `include_str!` 编译进二进制——改 pin 必须重编才生效（mac 实踩：补 pin 后不重编，install 仍报 no pinned asset）。
- 信任屏措辞随 agent 版本漂移（一轮 files→contents 三家全换）；settle marker 钉「菜单项短语」不钉「问句」，黄金行回归测试是防漂的锚（真身四路实踩三路 miss 后立此规矩）。
