# rust库搜索分析法实证

> 2026-08-31。编码经验研究的落地方法一：Rust 库搜索研发分析法。用户提供可脚本化方法综述（内置 CLI、第三方 CLI、HTTP API、Rust 客户端），本机逐条实证。

## 做了什么

- 实证内置 CLI：`cargo search` / `cargo info` 在本机 rsproxy 镜像下必须加 `--registry crates-io`（不加直接报错，素材未覆盖此环境）；`cargo info serde` 输出版本、license、features、repository 完整。
- 实证 HTTP API（带 UA，间隔 1s）：搜索 `sort=recent-downloads` 生效；单 crate 详情的 `max_stable_version` / `updated_at` / `repository` 可取；反向依赖结构订正——`.dependencies[].crate_id` 是被查 crate 自己，依赖方在 `.versions[].crate`、总数在 `.meta.total`（素材的取法会得到一列重复名）。
- 实证 jq 稳度筛选管道：`max_stable_version` 非空加 `recent_downloads` 阈值，terminal multiplexer 关键词筛出合理候选。
- 第三方 CLI（cargo-seek 等）与 crates_io_api 未装未编译，按需求标注 [经验]，不预先引入。
- 产出 `docs\research\rust库搜索研发分析法-CLI与API选型实证.md`：三级通道、稳度四信号、本机订正版工作流、坑表、与本仓规则关系（rmux-sdk 窄领域新库的复核例证）。

## 关键裁决

- 用户框架：落地方法六态齐后可形成规则。方法一已齐（核心路径 [实证]，可选工具按需 [经验]），等方法二到再统一升规则。
