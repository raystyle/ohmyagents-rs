# POC粘贴全CLI路线打通

> 2026-08-31。方案 0005 的 paste 部件在 Windows 验收绿。当天围绕「SDK 为什么发不出 paste」一路排障，最后落在全 CLI `-L` label 路线。

## 做了什么

- 写 `examples/poc-paste.rs` 并跑绿：中文 payload 经 `load-buffer` + `paste-buffer -p` + 独立 Enter 落进 pane，`capture-pane -p` 轮询到执行输出 `奥马粘贴成功`；收尾 `delete-buffer` + `kill-session`，无 kill-server。
- 排障链（全部本机实测）：
  1. SDK `Rmux::cmd()` 注入 `-S <pipe>`，CLI 报「Windows -S requires an explicit \\.\pipe\rmux-... endpoint」。
  2. 手工多形态实测 `-S`：完整 pipe 路径、裸名、SID 派生全名全被拒——报错文案误导，`-S` 在 Windows 无条件拒绝。
  3. 读 0.10.0 源码：`RmuxCommandKind::Request` 是纯 DTO，`Pane::transport()` 是 `pub(crate)`，裸 Request 逃生舱外部不可达。
  4. `-L label` 的报错曾误导为哈希形名；列 pipe 对比后发现 label 正名是 `\\.\pipe\rmux-S-<SID>-il-medium-<label>` 明文后缀，哈希形只是回落尝试。
  5. WMI 起 `start-server` 后 daemon 立即消失：exit-empty 语义，空 server 自动退。改 WMI 直接跑 `new-session -d`。
  6. WMI 返回早于 daemon 绑 pipe：首条本地命令前轮询 `list-sessions` 等 ready 后全链路绿。
