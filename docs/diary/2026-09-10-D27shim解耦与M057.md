## 流水

1. **D27 立项到落地**：用户裁「hook 不应该是 oma 本身，agent 工作过程中独占 oma 进程不能无痛升级轮换」加三平台 shell 指定（win cmd、linux bash、mac zsh）。`oma init` 先落自包含 shim 到 `.oma/hooks/`（三份全侧落齐），注册指向 shim，state 通道零 oma 依赖；secretguard fail-open 委托（oma 在位转发透传 exit 2，不在位放行）。状态栏无需改（本就是自包含 pwsh 脚本，agent 直跑脚本本体，运行时零 oma 依赖）。
2. **cmd shim 两级形态**：用户两句裁定「cmd 可以用 jq 命令啊（ome 管了 jq 的部署安装），shim 部署前可以检测 jq 命令是否在 path 上可用」。实现：部署前 `find_on_path("jq")` 探测；在位落 jq 版（字段提取与 state JSON 生成全走 jq `--arg`，程序体零裸双引号绕开 cmd 引号地狱；ts 用 `now|floor` 取纪元秒）；缺位落 findstr 回落版加 `init.hooks.warn` 指向 `ome install jq`。回落版初版用 token 位次硬切，实测 session_id 在 hook_event_name 后面时提取出伪值（session=PreToolUse），改锚定子串替换 `*hook_event_name":=` 剥前缀取首引号段（抗字段序、不造伪值；grok camelCase 事件名此形态降级 unknown，jq 形态才解析）。
3. **M057 根修**（D27 验收连带发现）：live verify codex 红 no-state-file。排查链：探针 shim 不执行，复刻 codex spawn（raw_arg 外层引号）直跑却绿，trace 日志加源码定位到真相：codex 的 hook 命令经**会话环境 shell** 执行（`core/src/session/mod.rs` 的 `environment.shell.derive_exec_args`，本机 world_state 实证 `shell:"powershell"`），不是 cmd。M056 的「cmd 直引号形态」前提错：直引号路径加参数在 PS 下是 ParserError（M047 同型），当时只经 `cmd /c` 直测验证、未跑真 codex。对照实测：直引号形态三事件全 Failed、`& "路径" codex` 调用操作符形态三事件全 Completed 且 state 落盘带真实 session id。教训：注册形态验收必须真消费方端到端实跑（codex exec / 无头 verify），单 shell 模拟不作数。存量用户级 `~/.codex/hooks.json` 里 M056 期直引号 oma 条目仍会 Failed，需用户手改或删（oma 不动家目录）。
4. **三端实跑验收**：Windows（jq 版七事件四态加 notification 形状区分、guard 真密钥 exit 2 委托、oma 缺位 fail-open、grok 包装、env 覆盖；findstr 回落版字段序翻转与缺事件诚实 unknown）加 WSL bash 双事件加 lan-mac zsh shebang 六事件（zsh 直跑、纪元 ts、guard 经在位 oma v0.3.0 委托）全绿。140 单元加 22 集成全绿（含 live verify codex 真机）。
5. **踩坑自记**：调试中给 shim 插桩的 `echo %PATH%` 在括号块里被 PATH 的 `(x86)` 提前闭合，自己造了一轮假线索（退出 255、`\NVIDIA was unexpected`）；cmd 批处理里环境变量含括号时禁止裸 echo 进括号块。

## 自省

- M056 修的是用户报的真症状，但根因归错了通道（把 grok 的 PS 语义外推反转为 cmd），验证又只走了模拟通道，于是「修好了」变成「换了个方向坏」。今天如果没有 live verify 这道真机判据，D27 的 codex 面会带病封版。
- 解耦的判断粒度：先分清短命 spawn 与常驻占用，hook 的真实痛点是升级瞬间文件锁与缺位盲区，自包含脚本加 fail-open 委托一次解两侧，不需要更重的常驻通道。
