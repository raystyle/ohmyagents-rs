# 四路会话工具：CLI 控制面与网页观察面

- 状态：进行中（文档已立，代码未开）
- 日期：2026-08-29
- 关联：五篇 `docs\research\`；现役定位见方案 0002

## 背景与问题

要在一个项目目录里同时跑 Claude、Codex、Grok、Kimi。人需要一条命令操作这四路，并在能开浏览器时看见原生 TUI。本方案是编排器的**首期切面**，不是产品上限。现役定位见 0002。

## 目标与非目标

- 目标：
  - CLI 为控制面：`oma check` / `init` / 默认 REPL / `send` / `status` / `cleanup`（项目名仍是 ohmyagents）
  - 浏览器为观察面：2x2 xterm.js，默认不弹窗；`--no-web` 可关
  - 四路写死，缺一则 check 失败
  - hook、skill、状态 JSON 只写启动的项目目录
- 非目标：
  - 本切面不实现完整 graph-of-loops、worktree、notifyd
  - 不引入 herdr 运行时
  - 网页广播栏当主入口
  - 自动安装 rmux（只在文档写命令）

## 方案

进程模型：

```text
pwsh/CLI  --drive-->  oma
                         |-- 可选 axum  --> 浏览器 2x2 镜像
                         +-- rmux-sdk   --> 专用 socket/pipe
                                              session 2x2 四路
```

Drive 以 evo-harness 三段式为准，详见研究《drive铁律与三段式粘贴》。状态通道为 `<project>\.ohmyagents\state\<agent>.json`，详见《agent状态通道》。平台与无浏览器详见《跨平台与无浏览器》。

## 备选方案

| 做法 | 取舍 |
| --- | --- |
| demo-orchestration：Claude 当编排器 | 否：控制面必须是本工具 CLI |
| broadcast-demo：Ratatui 卡片 + 自包 paste | 否：要原生 TUI 镜像；paste 不自包 |
| evo-harness 用户级 hook | 否：用户要求项目级 |
| CoreSkills project skill 元文件 | 否：文档骨架对照 ohmypwsh |

## 实施步骤

1. 文档骨架对齐 ohmypwsh（本方案所在这次交付）
2. 本机安装 rmux，版本写回研究
3. Cargo：check / cleanup
4. `init`：项目级 hook 与 skill
5. 2x2 spawn + CLI drive
6. 可选网页镜像；默认不 open-browser
7. Linux/mac/WSL 端点与 `--no-web` 验收

## 风险与回滚

- yolo 旗标关闭沙箱：只在信任目录跑
- 项目级 hook 弹信任框：spawn 前预写信任库，不改家目录 hook 注册
- Windows Job Object `os error 5`：提供 `--via-wt` 退路，不当默认
- 回滚：`cleanup` 只杀本 session

## 验收标准

- `docs\references\文档全量清单-方案与研究目录的完整索引.md` 与磁盘一致
- 无 `Cargo.toml` 直到步骤 3
- 步骤 3 之后：`check` 缺 rmux 非 0；四路齐才 0
- REPL `all` 四格都提交；`send kimi` 只动 Kimi
- `quit` 不拆会话；`cleanup` 后 session 消失
- 无浏览器时 `--no-web` 仍可 drive
