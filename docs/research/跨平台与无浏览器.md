2026-08-29

## 本机与对照项目的平台口径

写这篇的机器是 Windows。(2026-08-29 本会话 `user_info.OS = windows`，shell pwsh) `claude` / `codex` / `grok` / `kimi` 都在 PATH，`rmux` 不在。(同日 `Get-Command`)

| 平台 | 他们怎么说 |
|---|---|
| Linux / WSL2 | 已验证 |
| macOS | 预期可用 |
| Windows | 核心已备、待实测 |

win-rmux 只承诺 Windows + pwsh + wt。(skill frontmatter `compatibility`) web-claude-demo 和 broadcast-demo 的 Rust 代码按 `env::consts::OS == "windows"` 分支 named pipe，否则 unix socket。(`web-claude-demo/src/main.rs` `demo_rmux_builder`；broadcast-demo 同构 `WINDOWS_PIPE`)

demo-orchestration 同时给了 `launch.sh` 和 `launch.ps1`。(仓库目录) Windows 脚本里 agent 还包了一层 `powershell.exe -NoExit -File 临时.ps1`；broadcast-demo 后来改成 `pane.spawn(argv)`，更干净。(broadcast `launch_agent` / `split_agent`)

## 进程与 socket 怎么分

(据 demo 分支 + evo-harness `socket_name-{run_id}`)

| | Windows | Linux / macOS | WSL2 |
|---|---|---|---|
| rmux 端点 | `\\.\pipe\ohmyagents-<project-hash>` | `$XDG_RUNTIME_DIR` 或 `/tmp/ohmyagents-<user>/<hash>/socket` | 同 Linux（WSL 内是 Linux daemon） |
| 壳 | 不必强绑 pwsh；`spawn(argv)` 直接起 agent | 同，argv 不要套一层 bash -lc 除非必要 | 同 Linux |
| 探测命令 | `where.exe` | `command -v` | `command -v` |
| 浏览器 | 可选 `cmd /c start` | `xdg-open` / `open` | 默认不调 Windows 主机浏览器 |

socket 按**项目绝对路径做 hash**，不要所有仓库共用一根 pipe。evo-harness 用 `socket_name-{run_id}` 避免 `kill-server` 连坐。(`driver.py` L71–73 注释 smoke-12) 我们没有 run_id 也可以用项目 hash：两个仓库同时跑 `oma` 互不影响。

`cleanup` 只 `kill-session`，不 `kill-server`。(win-rmux 把无参 kill-server 当最后手段)

Windows 上若宿主在 Job Object 里，`new-session -d` / SDK `connect_or_start` 会 `os error 5`（`Windows refused to launch an independent RMUX daemon`）。[实证: 2026-08-29 本机 Grok 宿主 `poc-endpoint`] win-rmux 的退路是最小化 wt 跑 launcher。(SKILL launch 节) Oh My Agents 的默认仍是后台会话 + CLI，不弹 wt。POC 用 WMI `Win32_Process.Create` 在 job 外拉起 `libexec\rmux\rmux.exe --__internal-daemon <pipe>`，再 SDK `connect()`。[实证: 同日五条 pane POC 均 `poc.daemon.start=wmi-breakaway`] `--via-wt` 仍留作人眼可见的退路，不当默认。Linux/mac 的 socket 启动未在本机跑，后续委托环境仓库。[假设: POSIX `connect_or_start` 不经 Job Object]

## 网页：默认不弹，可以不要

web-claude-demo 默认 `serve` 并且 `attach` 占住终端，另有 `serve-only`。(`main.rs` args `check|cleanup|serve-only`) 它还打印 iPhone URL，监听 `0.0.0.0`。(`serve()` bind 与 println)

Oh My Agents 更硬一点：

1. **默认起 HTTP，不调用任何 open-browser。** 打印 `http://127.0.0.1:8080`，人自己开。无图形、SSH、CI、agent 宿主：复制 URL 或不管。
2. **`--open`** 才尝试系统 opener；失败只警告，退出码仍 0。
3. **`--no-web`** 不绑端口。四路照样 spawn，CLI 照样 drive，状态照样进 `.ohmyagents/state/`。
4. 绑定默认 loopback。要给同网段手机再显式 `--bind 0.0.0.0`（demo 默认全网卡，对我们过宽）。

WSL 里的服务在 WSL 的 `127.0.0.1`；Windows 浏览器要靠端口转发或 `localhost` 镜像，不能假定弹窗能跨到那一侧。(WSL2 localhost 转发因版本而异，需本机验证)

没有 DISPLAY / 没有 `xdg-open` / 没有 `wt.exe`，都不是错误。CLI REPL 才是操作会话的那条路。

## 镜像在备屏上仍然有意义

claude / kimi / grok 走 alternate screen，`capture-pane` 经常空。(win-rmux SKILL observe 节) 网页镜像走的是 PTY **字节流**（web-claude-demo 的 `PaneOutputChunk::Bytes`），不是 capture。所以「看动作」不依赖 capture。(据两种 API 不同) `--no-web` 时观察退回 hook 状态 + 人自己 `rmux attach`（可选）。

## 所以

Linux / macOS / WSL / Windows 共用一套 CLI 和同一套项目级文件；差别只在 rmux 端点字符串和命令探测。[推断: SDK 端点枚举 + 本仓 pathutil] 浏览器不是依赖。无图形环境用 `--no-web`。不要把 win-rmux「默认弹 wt」或 web-claude-demo「默认 attach + 听 0.0.0.0」带进默认路径。[实证: 2026-08-29 Windows pane POC 未弹浏览器、未 kill-server]
