# S024-四环境部署自适应矩阵

> 2026-09-02。缘起：Windows 侧 Claude Code 会话在本仓每个 prompt 弹 `UserPromptSubmit hook error: ENOENT uv_spawn '/mnt/d/ohmyagents/target/debug/oma'`，状态栏显示 `?? oma | ...`。用户定调根因：oma 没有针对四个系统环境（Windows、Windows-WSL-Linux 共享目录、Linux、macOS）的自适应部署管理。P0027 依据。

## 需求

- 核实：同一项目目录被多个环境消费时（典型：Windows 盘上目录同时被 Windows 原生与 WSL 打开），`oma init` 的 hook 注册与 `oma agents statusline` 配置如何做到一份注册全环境可用、消除「谁后跑 init 谁生效」的 see-saw。
- 事实源：Claude Code 官方 hooks 与 statusline 文档（2026-09-02 抓取）、S015 四家 schema 矩阵、本机实测。

## 关键结论

### 1. 现状破坏面

> 本仓实测取证。

[实证: 2026-09-02 本机]

- `.claude/settings.json` 8 个事件的 hook command 全是 WSL 侧写入的 `/mnt/d/.../oma`——Windows 侧 Claude Code exec form 直接 spawn 该串，uv_spawn ENOENT，**每次事件弹 non-blocking 提示**（官方口径：缺失可执行 non-blocking 但持续可见）。
- `.codex/hooks.json` 的 `command` 与 `commandWindows` **都**是 `/mnt/d` 路径——WSL init 把 Windows 专用字段也覆盖了；Windows codex 算出的 trusted_hash 对不上，信任失效弹屏（「非阻塞配置被破坏」的实感来源）。yolo 键本身（`approval_policy=never`、`sandbox_mode=danger-full-access`）未坏。
- 状态栏 `??`：`oma-statusline.ps1` 输出 🧽（U+1F9FD，码位合法）但未强制 UTF-8；装有 Git Bash 的 Windows 上 statusline 命令经 shell 路由，pwsh 子进程在 CP936 控制台把 emoji 替换成字面 `??`（实测输出字节 `3f 3f`）。

### 2. 四家注册的跨环境能力

> S015 加官方文档复核。

[实证: code.claude.com/docs/en/hooks、en/statusline，2026-09-02]

| 家 | 跨环境单串机制 | 依据 |
| --- | --- | --- |
| Claude | exec form `command:"oma", args:["hook"]`——command 按 **PATH 解析**后直接 spawn，各 OS 用自己的 PATH；无任何 per-OS 字段 | 官方 hooks 文档 Exec form 节 |
| Codex | 无 PATH 可依赖（hook 执行环境不继承 PATH，P0010 实测）；用原生 `command`（Unix 消费）加 `commandWindows`（Windows 消费）**双字段各填各的** | S015 源码 + 本机 0.149 实测 |
| Grok | 单 command 字段；sh -c 分支经 PATH 解析，bare `"oma hook"` 可行 | S015 源码 |
| Kimi | 无项目级 hook，不涉及 | S015 |

- homes 各 OS 独立（cargo bin 不在共享盘），绝对路径跨 OS **不可推导**——PATH bare 是 claude/grok 唯一通用单串机制。[推断: homes 布局]
- Claude statusline 命令经 shell 执行（装有 Git Bash 走 Git Bash，否则 PowerShell）；stdout 解码口径未文档化，但实测 `??` 出在 pwsh 编码侧，脚本内强制 `[Console]::OutputEncoding=UTF8` 即解。[实证: 本机修复后字节 `f0 9f a7 bd`]
- 用户定调 2026-09-02（多轮收敛）：状态栏对齐用户 starship 配置风格——完整目录路径、git 分支图标与状态旗标 `[!?]`（starship 符号语义）、`󰏗` 包版本、`󱘗` rust 工具链、`󰅐` 会话时长（成本数字对网关计价不准，不展示）、宿主 shell 段（含图标）；Catppuccin 系 256 色；oma 段 = **当前 agent 名 + 实时四态**（`󰚩 claude:working`，`:` 单字节分隔便扫屏匹配），状态源走 hook 状态通道（无 env 回退写项目文件）加会话闸。详见 S025。[实证: 本机渲染与扫屏匹配]

### 3. 形态阶梯与粘性

> P0027 落地口径。

- 探针 `find_on_path("oma")`（`which` crate，Windows 自动 PATHEXT）：命中写 **bare** 形态；未命中保持绝对路径形态（单环境项目行为不变）。
- **粘性**：已有 bare 注册不因探针未命中降级——否则一侧有 PATH 一侧没有时 see-saw 复辟。bare 且探针未命中时 init 打 `init.hooks.warn`。
- codex 字段所有权：Windows init 只写 `commandWindows`、Unix init 只写 `command`，**异侧字段逐字节保留**；永不 stale-drop oma 条目。双侧各跑一轮后注册文件收敛，任一侧重跑字节不变。[实证: 单测 codex_preserves_foreign_os_field_and_is_idempotent]
- codex 信任键内嵌各 OS 自己的 config.toml 绝对路径（`/mnt/d/...` 键与 `D:\` 键**共存不互覆**，本仓 config.toml 实见两族键）；每侧 init 重播本侧哈希即自洽。[实证: 本仓 .codex/config.toml]

### 4. 已知限制

- 探针假阴性：init 环境 PATH ≠ hook 执行环境 PATH（如 GUI 拉起的会话）时 bare 注册在本环境解析不到 → ENOENT；缓解：从带 cargo bin 的 shell 重跑 init。
- PATH 上的 oma 可能是旧构建（相对正在跑的 debug）；`init.hooks.form=` 标记可见。
- 双环境同名 agent 同时跑共写 `.ohmyagents/state/<agent>.json`（同物理文件），last-writer-wins，良性竞争。
- WSL 无 pwsh 时 statusline 配置部署成功但不渲染；`oma agents statusline` 打 `statusline.pwsh=missing` 警告（advisory）。

## 踩坑沉淀

| 坑 | 正解 |
| --- | --- |
| hook 注册嵌 `current_exe()` 绝对路径，共享目录跨环境互踢 | PATH bare（claude/grok）加 codex 字段所有权；bare 粘性 |
| 状态栏脚本输出 emoji 未强制编码 | ps1 首行 `[Console]::OutputEncoding = UTF8`，且必须在构造输出前 |
| 想给 bare 加「which 结果 == current_exe」same-file 守卫 | 拒绝：WSL 的 PATH oma 在 ~/.cargo/bin 而 current_exe 在 /mnt/d 调试目录，该守卫恰在最需要 bare 的场景退回绝对路径 |
