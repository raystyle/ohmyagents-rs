# 四路会话的控制面与观察面

2026-08-29

> 注（2026-08-31）：本篇定调的是**首期切面**；项目定位已升级为「通用智能体多路复用任务编排器」（见 `docs\proven\0004` 与 AGENTS 一、）。demo 拆解与两平面映射仍有效。

Oh My Agents 要做的事很窄：在一个项目目录里拉起 Claude、Codex、Grok、Kimi 四个终端 agent，**一条 CLI 操作这同一个会话**，浏览器只负责把四路 TUI 镜像出来给人看。网页不是主入口，弹不出浏览器也不该停工。

这句话听起来像把三份 rmux demo 叠在一起。叠之前得先拆开「声称」和「代码里到底做了什么」。

## 三份 demo 各管一段

[web-claude-demo](https://github.com/Helvesec/rmux-demos/tree/main/web-claude-demo) 证明一件事：浏览器和终端可以贴在**同一个** rmux pane 上。(`web-claude-demo/src/main.rs` 的 `handle_socket`：pane `output_stream_starting_at(Oldest)` 把字节塞进 WebSocket Binary，上行 JSON `data` 调 `keyboard().type_text`，`resize` 调 `pane.resize`) 它只跑一个 Claude，启动后还 `attach-session` 把当前终端占住。我们要四路，而且 CLI 不能被 attach 吃掉。

[broadcast-demo](https://github.com/Helvesec/rmux-demos/tree/main/broadcast-demo) 证明可以在一个 session 里 `split` + `spawn` 多个 AI CLI，底部一条 prompt 广播。(`broadcast-demo/src/main.rs` sha `b9d31ff`，`App::new` 对五个 pane `split_with`，`send_prompt_to_agent` 走 `PaneSet::broadcast`) 它的 UI 是 Ratatui 卡片，不是原生 TUI 镜像；缺某个 CLI 还会用已有的注水凑满五格。我们四路写死，缺一就失败，浏览器里要看到的是 agent 自己的界面。

[demo-orchestration](https://github.com/Helvesec/rmux-demos/tree/main/demo-orchestration) 才是「多路会话」的编排演示：Codex / Gemini / Grok 各占一个 session，Claude 拿着 `RMUX_DEMO_SOCKET` 当编排器，用户对 Claude 说 `Send Hi to all agents`。(`demo-orchestration/CLAUDE.md` 写死 `codex:0.0` 等 target；`launch.ps1` 用 `\\.\pipe\rmux-demo-orchestration`) 这和我们要的相反——我们不要第四个 agent 去操作另外三个，要**自己的 CLI** 操作四路。

同仓库这三份都该对照，但主入口不是 Claude 编排器，是 `oma` 这条命令（项目名仍是 ohmyagents）。

## evo-harness 已经把平面切开了

本机 `D:\sourcecode\evo-harness` 做的是同一四端（claude / kimi / codex / grok），但切法更干净：(`README.md` L71–80 与 `docs/interaction.md`)

- **控制平面**：rmux 后台会话里跑编排和 worker pane。
- **操作平面**：herdr 窗格给人看、给人点。
- 两平面只经文件总线交换状态，主对话不阻塞。

Oh My Agents 顺着这把刀切，换一套宿主：

| 平面 | evo-harness | Oh My Agents（(据上表推得)） |
|---|---|---|
| 控制 | flow 进程 + 四 worker pane | `oma` CLI（REPL / `send`） |
| 观察 | herdr monitor | 可选的 2×2 网页 xterm.js |
| 决策 | 主 agent + notifyd | 人在 CLI 里敲 |

不做 graph-of-loops、worktree、notifyd、herdr 插件。那些是编排器的事；我们是项目目录里的四路会话工具。

## 一条 CLI，浏览器可缺席

产品形状：(本会话用户定调)

```text
oma                 # 在当前项目目录起四路 + 可选网页，进入 REPL
oma --project D:\foo
oma send all "..."
oma send kimi "..."
oma status
oma cleanup
oma init            # 只往该项目写 hook / skill，见《项目级hook与skill》
```

REPL 里 `all` / `claude` / `codex` / `grok` / `kimi` 发 prompt，`quit` 只 detach。网页默认只镜像、不抢键盘。弹不出浏览器、SSH、CI、WSL 无 DISPLAY：CLI 仍然是完整控制面。细节在《跨平台与无浏览器》。

## 所以

控制面是 CLI，观察面是可选网页，会话钉在一个项目目录上。[推断: 对照三份 demo 与 evo-harness 两平面，本仓尚未把网页当默认依赖] 三份 demo 只借协议：镜像走 web-claude-demo 的 PTY 字节流，布局走 broadcast 的 split/spawn，隔离走 orchestration 的专用 socket。[经验: Helvesec/rmux-demos 与 evo-harness README] Drive、hook、平台分别写在后面几篇。
