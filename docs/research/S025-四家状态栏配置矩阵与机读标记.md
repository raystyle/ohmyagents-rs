## 关键结论

### 1. 四家配置矩阵

[实证: code.claude.com/docs、ohmypwsh S014/S016、MoonshotAI/kimi-code 与 xai-org/grok-build 浅克隆 2026-09-02]

| 家 | 配置落点 | 形态 | 外部命令 | 约束 |
| --- | --- | --- | --- | --- |
| Claude | `~/.claude/settings.json` `statusLine` | command 串经 shell（有 Git Bash 走 Git Bash） | 可 | stdin JSON 全量（model/context/cost/session_id）；路径用正斜杠 |
| Codex | `~/.codex/config.toml` `[tui] status_line` | 数组 `["command","pwsh",...]` | 可 | 无 stdin 数据；ohmypwsh S016 |
| Kimi | `~/.kimi-code/tui.toml` `[status_line]` `command` | 命令串首行接管 footer 第一行 | 可 | **300ms 超时**、1s 节流、64KiB 截断、只取首行；注入 env `KIMI_CODE_STATUS_LINE=1`；仅用户级（schema 在 apps/kimi-code/src/tui/config.ts） |
| Grok | `~/.grok/config.toml` `[ui.status_line]` | `type=builtin/command/disabled`（默认关）+ `command` + `refresh_interval` | 可，四家最强 | 最多 5 行、1024 字符/行、ANSI 与 OSC8、10s 超时；**repo 层注入整段剥除**（config_override.rs 防 cloned-repo 命令执行），仅用户级生效 |

- grok payload 最富（repo.host/owner/name、effort.level、turn.started_at_ms、trigger），缺源字段直接省略；kimi payload 有 model/cwd/gitBranch/contextTokens/sessionId。[实证: 源码 StatusLineContext / StatusLinePayload]
- oma 覆盖四家的写入点全部在用户级（各 OS home 独立，无跨环境冲突）。[推断: homes 布局]

### 2. oma 机读标记

> P0027 已落地部分。

[实证: 本机 2026-09-02]

- 形态：`󰚩 <agent>:<state>` 段，`:` 单字节分隔便于扫屏子串匹配（oma marker 风格）；state 四态 idle/working/blocked/unknown，色即语义（108 鼠尾草/179 金/203 软红/245 灰）。
- 状态源：`OHMYAGENTS_STATE_FILE` env（oma 会话）→ 项目 `.ohmyagents/state/<agent>.json` 回退；**hook 无 env 回退写**（agent 名由注册参数 `--agent <名>` 注入、项目根从 payload cwd 沿 `.git` 上溯）——用户手拉的 agent 会话状态通道同样活（实测本会话 PreToolUse 实时写 working）。
- **会话闸**：状态记录带 `session`，状态栏 payload 的 `session_id` 不匹配 → 按未知处理——死会话遗留态不再冒充当前态（实测旧文件被闸、本会话实时态通过）。
- agent 名：OMA_AGENT env 优先（oma 拉起），部署参数次之（claude 配置注册时带 `claude` 参数）。
- 附带段：宿主 shell（祖先链跳过 agent 本体找最近 shell；Linux 走 /proc、macOS 走 BSD `ps -o ppid=`、Windows 走 `Get-Process .Parent`）——同样可作机读信号。

### 3. rmux 编排消费

> 后续切片。

- oma 已有原语直接可用：`expect_visible_text`（S005 send 确认短头同型）、output_stream 画面捕获、settle 扫屏。消费口径：扫 `<agent>:working|idle|blocked|unknown` 子串。
- 价值：hook 依赖 env 注入（oma 会话才有）；TUI 标记任何会话都画——用户手拉的 agent 也能被编排感知（验收/诊断盲区补齐）。
- 待立项：`oma status`/`doctor` 增加「扫屏态 vs hook 态」交叉核对行；grok `refresh_interval` 定时刷新可作准实时心跳。

## 踩坑沉淀

| 坑 | 正解 |
| --- | --- |
| kimi 300ms 预算内跑多段子进程（git/rustc/shell 链） | 状态栏脚本各段静默失败不致命；kimi 侧超时自动回退内置布局，验收时核对首行是否接管 |
| grok repo 层 `[ui.status_line]` 写了不生效 | 安全闸使然（防克隆注入）；oma 只写用户级 `~/.grok/config.toml` |
| 状态文件被死会话遗留态污染 | 记录带 session、状态栏会话闸比对 session_id |
