## M061 codex hook 信任键源用错定义文件路径

- 2026-09-11，D28 codex review F1 发现（P0010 期引入，跨 v0.5.x 存活）。
- 现象：oma 预种 `[hooks.state]` 后 codex 仍判 oma hook Untrusted，`codex exec` 无 bypass 静默不跑（状态栏 codex 恒 unknown）；历次 live verify 全绿是因为 argv 恒带 `--dangerously-bypass-hook-trust`（假绿掩蔽）。
- 根因：信任键 `<key_source>:<label>:<g>:<h>` 的 key_source 是**定义该 hook 的文件路径**（用户层 = `~/.codex/hooks.json`，discovery.rs 的 load_hooks_json 返回 source_path），oma 从 P0010 起一直传 config.toml 路径；P0010 已记「hash 复现未全中，仍弹 Hooks need review」未被深究。
- 正解：键源 = hooks.json 路径（`codex_trust_entries` 收定义文件路径）；哈希算法本身（键排序 JSON 加 sha256，Windows 取 commandWindows 且 identity 丢弃该字段）与 codex 同构无需动。判据锚：无 bypass 的 `codex exec` 落盘 state 才算真绿。
- 教训：信任预种的验收必须走「无 bypass 真触发」路径；带 bypass 的 verify 绿不覆盖信任面。
