# 测试标准细则-分层断言与门禁流程

> 角色：**本仓测试规则**。AGENTS 操作规则 11 的细则，三层展开——**分层与目录**、**断言与命名**、**门禁与演进**。
> 依据：三源对照研究 `docs\research\Command-LineRust测试方法论与oma测试分层.md`（书 2022 地基、2026 社区综述、microsoft/rust-guidelines `c1d2efc`）。本文事实性断言标六态溯源，标准见 `docs\guide\研究标准细则-结构与六态标记.md`。

## 一、分层与目录

> 分层按官方三层；oma 的 examples 是第四形态：POC 验收原型。

| 层 | 落点 | 测什么 | 约定 |
| --- | --- | --- | --- |
| 单元 | 源码同文件 `#[cfg(test)] mod tests`，`use super::*` | 私有 API、单函数边界、错误路径、不变量 | 正式构建不含测试代码 |
| 集成 | `tests\*.rs`，每文件独立 crate | 仅公开 API、模块协作、对外契约 | 不写 `#[cfg(test)]`；共享夹具放 `tests\common\mod.rs` 用 `mod common;` 引入 |
| 文档测试 | `///` 内 ```` ```rust ```` 代码块 | 公开 API 示例可编译可运行 | `cargo test --doc` 单独跑；lib 公开面少则暂不写 |
| POC 验收 | `examples\poc-*.rs` | 部件行为（退出码 + `poc.*` 标记行） | 闸门不满足立即失败退出；结束只 `kill-session` |

- 能用集成覆盖就不用单元：集成不依赖内部结构，重构时更稳。[实证: rust-guidelines M-INTEGRATION-TESTS；书第 3 章同向]
- `tests\` 每个顶层 `.rs` 是独立 crate；`tests\common\mod.rs` 不会被当成独立测试目标。[经验: 官方 cargo 约定]
- oma 现状：`src` 内已有模块级单元测试（端点形状、错误分类）；`tests\` 尚未建。[实证: 2026-08-31 查本仓]

## 二、断言与命名

> 意图对应方法；期望值必须有独立来源。

### 1. 意图到方法

| 意图 | 方法 | oma 对应 |
| --- | --- | --- |
| 冒烟（活着即可） | 断退出码 0 | `oma --version`、`oma check --no-install` |
| 集成（用户方式整跑） | assert_cmd 跑二进制，断 stdout/stderr/退出码 | `oma agents`、`oma hook`（stdin 喂事件断 state 文件） |
| 回归（改动不破旧） | 黄金文件全量重跑 | `tests\expected\` 对齐 `poc.*` 标记行 |
| 验收（对照外部标准） | oracle 生成期望 | POC example 本身 |
| 不变量（任意输入成立） | 属性测试 | 版本串解析、TOML 往返（后置） |
| 性能 | 基准工具，不进断言 | 目标外 |

### 2. 断言规则

1. **期望值来自独立来源**：规范、黄金文件、属性约束。不得用被测同款逻辑复述期望值，不得镜像实现分支——重言式测试按构造通过，纯噪声，AI 生成测试高发。[实证: rust-guidelines M-TAUTOLOGICAL-TESTS]
2. **只断稳定字段**：标记行、退出码、stderr 关键词；放过 pid、时间戳、机器差异（owner、列宽、目录大小）。[实证: 书第 14 章 Testing Underground]
3. **一个测试一件事**；失败信息能定位（panic 消息带原因与实际值）。[实证: rust-guidelines M-PANIC-MESSAGE]
4. **正例负例成对**：`success()` 与 `failure()` 对应写；无参数应失败并打用法是标准负例。[实证: 书第 1-2 章]
5. **错误路径必须覆盖**：空输入、缺文件、权限失败、超时，不只测 happy path。[经验: 三源共同原则]
6. **测试体错误传播**：`type TestResult = Result<(), Box<dyn std::error::Error>>`，用 `?` 代替 `unwrap`。[实证: 书第 2 章]
7. **输出无序时双侧 sort 后比对**（session/pane 列表类）。[实证: 书第 7 章]

### 3. 命名

- 测试名写成可读规格：动词加条件加预期（如 `login_locks_after_three_failures`）。[经验: 社区惯例]
- 期望失败的负例名带 `dies_` 前缀，`cargo test dies` 可过滤。[实证: 书第 2 章]
- 常量收敛：测试文件顶部 `const PRG` / 路径常量用全大写。[实证: 书第 3 章]
- 重复模式收进 helper（`run(args, expected)` 形态）。[实证: 书第 3、14 章]

## 三、依赖与闸门

1. **测试依赖白名单**：`[dev-dependencies]` 只进 assert_cmd、predicates（按 crates.io 现版复核后引入）；rstest、insta、proptest 等各设触发条件（见第五节），不预先引入。[推断: AGENTS 写 Rust 规则的最少依赖原则对测试的适用]
2. **mock 策略**：oma 拿真 rmux daemon 集成，不默认 mock；时钟、熵源等非确定边界若进产品路径，留 trait 注入口。[实证: M-MOCKABLE-SYSCALLS 与本仓 POC 全程真依赖的调和]
3. **rmux 闸门**：依赖 daemon 的测试先查 pin（`oma check --no-install` 语义），缺则 skip 并说明，不失败、不装、不 `kill-server`。[推断: 本仓 POC 闸门模式延伸]
4. **测试设施 feature gate**：桩 agent 注入、hook 事件伪造、安全旁路收进单一 `test-util` feature；闸门 skip 不算旁路。[实证: rust-guidelines M-TEST-UTIL]
5. **环境夹具**：临时目录、临时 label；测试自清理（删临时文件、kill 本 session）。[实证: 本仓 poc-paste 与 yolo POC 已此法]

## 四、门禁

> 最小集本地化；CI 化后按第五节扩展。

1. **本地门禁三件**：`cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --locked`。
2. **锁文件**：Cargo.lock 已入仓，测试跑 `--locked` 防依赖漂移。[经验: 社区门禁惯例]
3. **慢测**：daemon 类与压测类不进默认路径；标 `#[ignore]` 或独立 example，默认反馈保持秒级。[实证: 书 biggie 分离原则]

## 五、演进路线

> 三段式，每段绿了再进下一段；对应研究文档待办。

| 段 | 时机 | 内容 |
| --- | --- | --- |
| 第一段 | 本目标内 | `tests\cli.rs` 建档；check/agents/hook 冒烟与负例；本地门禁三件；AI 自检规则生效 |
| 第二段 | 产品命令期 | POC 转回归（闸门 skip）；MISTAKES 行配测试；测试上量后引 cargo-nextest（doctest 仍 `cargo test --doc`）；status 复杂后上 insta 快照（CI 禁静默改快照） |
| 第三段 | 按需 | GitHub Actions 门禁（fmt/clippy/nextest --locked/audit）；proptest、llvm-cov（观测不门禁）、mutants（夜间）、多 OS 矩阵；criterion 等出现需求再立项 |

## 六、AI 协作自检

> 本仓为 AI 协作仓，写测试前过一遍。

1. 期望值是否来自独立来源？若来自「我刚写的实现」，停，换规范或黄金文件。[实证: M-TAUTOLOGICAL-TESTS 点名 Agent 高发]
2. 是否先复现再固化？bug 修复先写失败测试再改代码。[经验: TDD 红绿循环，书第 3 章]
3. 断言的是行为（公开输出）还是实现（内部结构）？内部重构不应炸测试。
4. 快照与黄金文件不自动接受；变更必须可审。[经验: 社区快照纪律]

## 七、与六态的衔接

- 测试绿是 `[实证]` 的最强依据：研究文档断言可引用测试名（如 `[实证: tests\cli.rs::dies_no_args 2026-08-31]`）。
- POC example 转回归前后，研究文档里的实证标注不变来源；转回归只是让该实证可重复。
- 未落地的门禁项（nextest、CI）在研究文档保持 `[记忆]` 或 `[推断]`，不因写入本文升级。

## 八、验收自查

写完测试自查：

1. 分层落点正确（单元在 `#[cfg(test)]`、集成在 `tests\`、公开 API 不塞 `mod tests{}`）
2. 期望值有独立来源；无重言式断言
3. 断言只含稳定字段；正负例成对；错误路径有覆盖
4. 命名可读；负例带 `dies_`；重复收 helper
5. rmux 依赖有闸门；测试自清理；临时物不残留
6. 本地门禁三件通过
