# 看板资源包化

- 状态：已完成（2026-09-01 当日达成，释放与托管全链验收）
- 日期：2026-09-01
- 关联：研究 `S022`（三路线裁决：嵌入归档加首启释放）；用户定调「web\share-src 应该是在源码里，安装释放到用户应用数据目录，研究 rust 编译的程序如何自带资源包解压安装」「自带 web 看板网页 JS 资源包解压安装」；前置 `P0022`（此前 serve 读仓库 `docs\web\kanban`——克隆仓才可用）

## 背景与问题

oma 是可安装产品（exe + 自管数据根 `~/.ohmyagents`），但看板前端资产躺在仓库里被 serve 运行时读盘——开发态专属，装出去即坏。要求：单 exe 自带资源包，首次（或指纹变更）运行释放到用户应用数据目录，与 rmux/agent 安装同一哲学。

## 方案

> S022 路线 C：嵌入归档加首启释放。

- **build.rs**（本仓首个）：`docs/web/kanban` 递归收集（相对路径正斜杠稳定入包、按路径排序保字节可复现）→ `tar.gz`（`tar`+`flate2`+`sha2` 进 build-dependencies，运行时同版本零新 crate）→ 写 `OUT_DIR/kanban-web.tar.gz` 与 `kanban-web.fingerprint`（包字节 sha256 前 8 位）；`cargo:rerun-if-changed=docs/web/kanban` 声明资产依赖；缺 `index.html` 直接 panic 提示先跑前端构建。
- **`src\webassets.rs`**：`include_bytes!`/`include_str!` 经 `OUT_DIR` 嵌入；`ensure_web_assets_at(home)`——指纹目录 `<home>/web/<指纹>/` 有 `index.html` 即复用；**每次调用都清非当前指纹目录**（一次一份不积堆）；缺则内存解压（`GzDecoder<&[u8]>` + `tar::unpack`，错误带路径）。home 参数化便于测试。
- **server.rs**：`ServeState` 加 `kanban: PathBuf`；两处 serve 入口 ensure 后塞 state；三个静态 handler 与 `home`（注入 shim）都从释放目录读；banner 打 `serve.kanban=<释放路径>`。
- 仓库保留 `docs/web/kanban`（构建输入，无 node 也能 `cargo build` 出带资源的产品）与 `share-src`（其源）。

## 验收标准与结果

- 单测四件：指纹 8 位 hex；释放→幂等→污染重建→旧指纹不积堆（首版幂等分支不清旧目录被测试抓住，改为「无论复用与否都清非当前」）；包内必带 `_astro`（wasm 空白事故的回归钉，P0022）。过。[实证]
- 活体：删 `~/.ohmyagents/web` → `oma serve` 首启自动释放 `web/04d458c5/`（banner 打印）→ home 200、title「Oh My Agents 工作看板」、wasm 200，全部从释放目录出。过。[实证]
- 基线：74+10（无 feature）、77+10（server,mcp）全绿。过。[实证]

## 实施过程与经验

- `include_bytes!(concat!(env!("OUT_DIR"), ...))` 是编译期资产交接的标准缝；`rerun-if-changed` 让前端 rebuild 自动触发重打包重编，不用手动清理。
- 释放语义的单位是**内容指纹目录**不是版本号：前端迭代与 oma 版本解耦，指纹变即重释放，同指纹幂等。
- 「清理」是幂等性与重释放两条路径都要做的动作——首版只在重释放分支清，被单测的「伪造旧目录」用例当场抓获：谓词类逻辑先写边界用例的教训第 N 次兑现。
- build.rs 的 `main` 不能用 `?`（不返回 Result），expect/panic 即可；build 阶段失败信息直接指路（缺 index.html 提示先跑前端构建）。
