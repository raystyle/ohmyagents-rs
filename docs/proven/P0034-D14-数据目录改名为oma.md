# P0034：D14 数据目录改名为 `.oma`

> 2026-09-07 当日闭环。用户原话先写 `.omc`，随即纠错「失误 我们的目录应该是oma」。ohmycloud 已占用 `.omc` / `~/.omc` / CLI `omc`。

## 方案

1. **两根同改**：项目 `<cwd>/.oma` 与家目录 `~/.oma`，同一常量 `pathutil::DIR`。
2. **迁移**：仅旧 `.ohmyagents` 在、新目录不在则 `rename`；两者都在则用新名、旧目录不动；都无则默认新名。
3. **不动**：技能目录名 `ohmyagents`、Grok hook 文件 `ohmyagents-state.json`、`%LOCALAPPDATA%\ohmyagents` 旧 rmux 位、`OMA_HOME` 覆盖。
4. **状态栏**：ps1 双读 `.oma` 再旧名（TUI 不经 Rust 迁移）；家目录迁完后 `oma agents statusline` 重写四家配置路径。

## 验收

- `data_dir` 三态单测绿。
- `cargo test --lib` 145 过。
- 本仓 `.oma` 在、`.ohmyagents` 不在；家目录 `~/.oma` 在；Grok/Claude/Kimi 状态栏 command 指向 `~/.oma/statusline/`。

## 实施过程与经验

- `.omc` 会与 ohmycloud 金库撞名，澄清轮拦住了。
- M004 2026-08-29 曾否决 `.oma`（当时怕和 CLI 名混用）。D14 用户裁定覆盖：仓库仍 `ohmyagents-rs`，命令仍 `oma`，数据目录改回 `.oma`。
- 临时目录测试必须带原子计数器，否则并行用例会抢同一毫秒路径，迁测假失败。
- 家目录 rename 后，已写入各家 config 的绝对路径不会自己变，必须重放 `oma agents statusline`。
