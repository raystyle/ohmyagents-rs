## 背景与问题

P0017 口径的缺口清零后，按「产品完备可用」严格口径仍剩三件：门面文档停在 POC 时代、SSE 对真 agent 是转义汤、四家真路只有 claude 完整验收过。本方案一次收口，真路验收又揪出四个真缺陷当场修掉。

## 方案与切片

1. **SSE 渲染行流**：`/stream/{agent}` 从原始字节切 `line_stream`（按行加 lossy UTF-8）——实测证明它的「渲染」不含终端仿真，真 TUI 仍带 ANSI。
2. **README/CHANGELOG/ROADMAP 对齐现状**：从「spawn 尚未落地」的 POC 口径对齐到十八方案十四命令；ROADMAP 阶段 1 至 4 全已完成、阶段 5 排后。
3. **四家真路全链验收**：真 spawn、真任务下发、hook 状态流、settle 信任、网页画面、trace 检索各走一遍。

## 真路验收揪出并当场修掉的缺陷

1. **`oma status` 一路死拖垮整条**：codex 路退出后 status 直接报错不输出。修：逐路降级——pane 消失该路报 `terminal=dead`，其余照报（死路本身正是要看的信息）。
2. **claude 路继承 `CLAUDE_CODE_CHILD_SESSION` 关闭 transcript**：oma 从 Claude Code 会话里拉起的 claude（画面警告「Transcript saving is off」）不写会话 jsonl，联邦 trace 检索不到。修：spawn 的 claude 路注入 `CLAUDE_CODE_CHILD_SESSION=`（空）加 `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE=1`。三证验收：警告消失、会话文件落盘、pane 里真 claude 的 Write 编辑事件被 trace 检索到（`b1e670d3:call_3c49…`，file=.ohmyagents/acc-scratch.md）。
3. **SSE 转义汤的正解是 render_stream 不是 line_stream**：新端点 `GET /screen/{agent}`——daemon 侧 surface 投影（非视觉输出已过滤），每次更新发全屏 `visible_lines`（JSON 数组），并补首帧快照（render_stream 只在变化时推，静屏连接会空白）。网页画面加「镜像/日志」双模式。实测 claude TUI 36 帧全屏纯文本，`❯` 输入框、状态栏、context 百分比全部干净可读。
4. **settle 三处不足**：只扫屏底 12 行（codex 升级屏在屏顶、kimi 信任菜单在屏中，全漏）；kimi 信任框默认焦点在「Don't trust」，裸 Enter 选了不信任直接退出；codex 升级提示屏无处置。修：全屏匹配；白名单升级为 (marker, key 序列) 三态——claude 信任 Enter、kimi `Up+Enter`（先移焦点再确认）、codex 升级屏 `2+Enter`（Skip，自动升级不属 settle 职责）。

## 已知差异（记录不阻塞）

1. **kimi 输入框单 Enter 不提交**：oma send 的「文本→等回显→Enter」在 kimi 的多行输入框里只进缓冲，补发一个 Enter 才提交（三段式粘贴同理）。修复方向：send 对 kimi 的提交键序列特化，另立小方案。
2. **codex 用户级 hook 审查屏留手动**：`~\.codex\hooks.json` 里用户自己的 hook（secret-guard）变更触发审查，settle 不自动 toggle——自动信任 hook 等于替用户授权命令执行，越权。
3. **grok 首轮 send 偶发未提交**（本仓主菜单层焦点）：干净项目直通；机理待 kimi 同族排查后一并看。

## 实施过程与经验

- 真路验收的价值密度远超 stub：stub 全绿的四路，真路上当场死两路（codex 升级屏、kimi 反向焦点）——**stub 验证协议，真路验证世界**。
- 诊断靠的还是自家工具链：`/screen` 镜像看画面、`trace` 查各家会话库、`oma status` 看链路——oma 在给自己做验收时完成了自举。
- `line_stream` 的「rendered」教训：读 API 文档要读到语义边界（行渲染不等于终端仿真），surface 投影（render_stream）才是网页要的；首帧缺口是「只在变化时推送」流模型的必然，补一帧快照即圆。
- CLAUDE_CODE_CHILD_SESSION 是环境继承类 bug 的典型：spawn 只想着注入自己的 env，没想着清掉不该继承的——「注入面」和「清洁面」要一起管。
