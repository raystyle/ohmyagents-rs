# 各功能部件POC验证原型

- 状态：已完成（Windows 范围全表绿 2026-08-31；Linux/mac pane 跑测委托后续仓库）
- 日期：2026-08-29 至 2026-08-31
- 关联：`GOAL.md` 当前目标；研究 `docs\research\S003-rmux-sdk最佳开发实践与验证poc.md`；方案 0001 首期切面、0003 `oma check`

## 背景与问题

文档骨架、定位、`oma check` 已落地。产品命令（spawn / send / init / doctor / cleanup / 网页）尚未实现。用户定调：**先做各功能部件需求的 POC 验证原型**，再叠成 `oma` 产品命令。避免一次写完整编排器却在 drive / 布局 / 清理上踩已知坑。

## 目标与非目标

- 目标：
  - 按部件拆最小可跑原型，每件有验收：退出码 + 可观察产物
  - 落 `examples/poc-*.rs`，`cargo run --example poc-<名>`
  - 用 `rmux-sdk = "=0.10.0"`；缺一等 API 再走协议/CLI 逃生舱
  - 闸门：`oma check` 已绿（本机 Windows 已装 0.10.0）
- 非目标：
  - 本轮不实现完整 `oma spawn` / REPL / 网页 HTTP
  - 不先上四路真实 agent（布局/drive 用 pwsh echo 桩）
  - 不 `kill-server`、不默认弹浏览器、不抄 CreateOrReuse 叠窗格

## 风险与回滚

- Job Object `os error 5`：记 MISTAKES；POC 用 WMI 在 job 外拉起 daemon 再 `connect()`，不当默认 kill-server，不把 wt 当默认
- paste 协议构造失败：退 CLI `paste-buffer -p`
- 回滚：删 example 会话名；不碰用户其它 rmux 会话

## 验收标准

- 每个待办部件有 `examples/poc-*.rs` 且本机 `cargo run --example …` 退出 0。pane 最小集（endpoint/session/layout/drive/dialogs/paste）已在 Windows 验收；Linux/mac 委托后续仓库
- 负例不作为「成功路径」合入 `src/`
- `oma check` 仍绿；POC 不调用 `kill-server`
- 清单、GOAL/TODO/PLAN 与磁盘一致

## 实施过程与经验

### negatives（2026-08-31，Windows 绿；全表收官）

- C-c 守卫落 rmuxpoc `check_send_key`：codex 加一切中断形态（`C-c`/`c-c`/`^C`/`\u{3}`）Err，claude 放行、codex 的 Enter 放行——per-agent 策略不是一刀切。POC 实证守卫 throw 后桩 pid 不变（没漏发）。[实证: 单测 + poc-negatives 标记行 `c_c_codex.survived=true`]
- 只杀本 session 的实证法：同 daemon 起兄弟会话，杀自己后兄弟仍 listed 且 daemon 仍应答（ReuseOnly 往返）——不碰用户其它 rmux 会话。[实证: `sibling_alive=true`、`daemon_alive=true`]
- daemon-wide kill 的静态负检只扫 `src\`（验收口径是负例不进产品成功路径）；examples 里宣示规则的注释属合法提及，扫进去是误报。[经验]
- Quiet 超时不当 idle 已由 poc-state 实证（见 state 节）；cleanup 只断言本 session 名消失已由 poc-session 实证。

### init（2026-08-31，Windows 绿）

- 前置一手研究 S015（四家注册形态源码核实）后才动手：Claude 用 exec form（`command`=oma.exe 绝对路径 + `args:["hook"]`，无 shell 引号问题）；Codex 落项目 `.codex\hooks.json`（与 config.toml `[hooks]` 是孪生表示，同层双写会触发「prefer single representation」警告，故只写 JSON）加 `commandWindows`，并在 `.codex\config.toml` 合并 `[features] hooks = true`（win-rmux 先例）；Grok 落 `.grok\hooks\ohmyagents-state.json`（Claude 同构，command 单字段带引号加参）；Kimi 项目级 hook 注册不存在（local.toml 只收 workspace.additional_dir），只落 skill 目录。[实证: S015 + poc-init 标记行]
- 部署在 `src\deploy.rs`（`oma init` 的产品层，暂未接 CLI）；merge-only：外条目原样保留、按 oma 二进制标记去重、换路径的旧 oma 条目替换为新路径（裸名 `oma` 与含当前路径的不算 stale）。幂等二次部署零写入零字节变更。[实证: 2 条单测 + poc-init `init.idempotent=true`]
- 家目录不动是硬断言：POC 对 `~/.claude(settings+json)`、`~/.codex(config+hooks)`、`~/.grok/config`、`~/.kimi-code/config` 六文件 SHA256 前后指纹对照，`poc.home.untouched=true`。[实证]
- 用户已有 `AGENTS.md` 不覆盖（skip）；`CLAUDE.md` 只在缺失时写一行 `@AGENTS.md`；skill 以 `.agents\skills\ohmyagents` 为源拷三份（Claude 不扫 `.agents/skills`）。
- 实现坑：drop-stale 去重初版把当前 exe 自己也删了（每次重部署都重加）；判 stale 必须只针对「嵌了不同 oma 路径」的命令，裸名与含当前路径的保留。同轮还修了 grok 断言把带参命令串当纯路径查尾的错。

### state（2026-08-31，Windows 绿）

- 最小 `detect_terminal_state` 落 rmuxpoc 共用层：输入 `PaneSnapshot::visible_lines()` 加 cursor row/visible；优先级照 clum——password（tail，col 0 也命中）> confirm（tail）> 光标不可见即 Running > 提示符行（tail 是 `PS …>` 且可见光标停在该行）才 Ready > Unknown。7 条单测覆盖 col-0 password、提示符行错位、光标隐藏、中文缺口。[实证: cargo test 7 过]
- 核心断言达成：`wait_until_stable_for` 静止成立（revision 不变）时 verdict 仍非 idle（unknown）， Quiet 只当 Drive 同步信号；命令完成后经同一通道回 idle。[实证: poc-state 标记行 `quiet.stable=true`、`quiet.not_idle=true`、`quiet.verdict=unknown`]
- 双阻塞形态可从画面判：confirm tail（`[y/n]`）→ blocked，`y` + Enter 点掉后 `ANS=y` 可见回 idle；password tail（`Password:`）→ blocked，之后只发裸 Enter 放行 Read-Host，不往输入打任何内容。hook 全程沉默，权威走 1b 兜底。[实证: poc-state 标记行]
- 已知缺口照 S010：纯中文确认词（`是否继续？`）不在关键词表，落 Unknown 不误判 idle；中文关键词表生产前再扩。测试输入坑：`是否继续？(y/n)` 含 ASCII 标记会正确命中 Confirm，测缺口必须用纯中文行。

### stream（2026-08-31，Windows 绿）

- 两条流语义都验证：`PaneOutputStart::Oldest` 从保留 backlog 头回放（首块 sequence=0），`Now` 锚定在当前最新之后只发新字节，旧 marker 不出现在 Now 流。[实证: poc-stream 标记行 `oldest.first_seq=Some(0)`、`now.no_replay=true`]
- 字节流是原始 bytes（可含 NUL 与非 UTF-8），chunk 带 daemon 侧单调 sequence；收集侧用 `Vec<u8>` 累积加 ASCII 子串匹配，`from_utf8_lossy` 只做展示。echo 发出到流中见到 marker 约 11ms，网页镜像直连此流即可，POC 不开 HTTP。[实证]
- 踩坑（M027）：live marker `OMA-POC-STREAM-NOW` 包含 backlog marker `OMA-POC-STREAM` 子串，no-replay 断言被自己的 live 输出命中。多 marker 同流断言必须互不为子串。

### locate（2026-08-31，Windows 绿）

- SDK 只给 pid 不给进程名：`PaneProcessState::Running { pid }` 无 name 字段，进程名必须 OS 反查。[实证: 0.10.0 源码 `info.rs:245`]
- 反查实现：一次 pwsh `Get-CimInstance Win32_Process -Filter 'ProcessId=a OR …'`（批量单查询），输出 `pid=name` 行解析；死 pid 不出现在结果即代表不存在，无需二次确认。非 Windows 走 `ps -p … -o pid=,comm=`（Linux/mac 委托后续仓库）。[实证: poc-locate 输出四格全部 `pwsh.exe`]
- 错位语义按 S003 POC-6 口径落地为 `expect_process` 守卫：pid 缺失（死/回收）与名字不符都返回 Err，禁止 warn-and-continue；守卫放在每次 `send_key` 之前（`send_key_checked`）。匹配用大小写不敏感 contains，兼容 `pwsh.exe` 全名与 `pwsh` 短名。[实证: poc-locate 中死 pid、`notepad` 错位、守卫负路三处都 throw，正路 marker 可见]
- 教训：探针断言写反方向——POC 对负例的要求是「必须 Err」，若负例返回 Ok 要让 POC 失败退出，防止守卫形同虚设。[经验]

### paste（2026-08-31，Windows 绿）

- 原设想「SDK 协议建会话 + CLI paste」混合路线不成立。0.10.0 源码核实：`RmuxCommandKind::Request` 是惰性 DTO，`Pane::transport()` 是 `pub(crate)`，外部无裸 Request 发送口；`Rmux::cmd()` 在 Windows 注入 `-S <pipe>`，而 CLI 对一切 `-S` 形态无条件拒绝（含 `\\.\pipe\rmux-...` 前缀、裸名、SID 派生全名）。[实证: 2026-08-31]
- 实际路线为全 CLI：`-L <pid+tag label>` 专用端点。label 的 daemon pipe 名是 `\\.\pipe\rmux-S-<SID>-il-medium-<label>`（label 明文后缀）；client 报错里出现的 `g-<hash>-<salt>` 形是回落的哈希名，不是 label 正名。[实证: 2026-08-31 列 pipe 对比]
- Job Object 下 WMI 起 daemon 的启动命令必须是 `new-session -d` 而非 `start-server`：空 server 会因 exit-empty 立即退出。WMI 返回早于 daemon 绑 pipe，首条本地命令前要轮询 `list-sessions` 等 ready。[实证: 2026-08-31]
- 三段式验证达成：payload 文件（UTF-8 中文、无换行、无 ESC）经 `load-buffer -b` + `paste-buffer -p -b -t session:0.0` 粘入，Enter 单独 `send-keys`，`capture-pane -p` 轮询到执行输出行。marker 用拼接式（`('奥' + '马粘贴成功')`）区分回显行与执行行，防「回显命中」假阳性。[经验: evo-harness driver 同款三段式，本仓首次在 Windows 实跑中文]
- 收尾只 `kill-session` + `delete-buffer`；label daemon 随末 session 自动退出（exit-empty），无需 kill-server。临时 payload 文件删除。
