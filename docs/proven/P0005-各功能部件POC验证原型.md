## 背景与问题

文档骨架、定位、`oma check` 已落地。产品命令（spawn / send / init / doctor / cleanup / 网页）尚未实现。用户定调：**先做各功能部件需求的 POC 验证原型**，再叠成 `oma` 产品命令。避免一次写完整编排器却在 drive / 布局 / 清理上踩已知坑。

## 目标与非目标

- 目标：
  - 按部件拆最小可跑原型，每件有验收：退出码 + 可观察产物
  - 落 `examples/poc-*.rs`，`cargo run --example poc-<名>`
  - 用 `rmux-sdk = "=0.10.0"`；缺一等 API 再走协议/CLI 逃生舱
  - 闸门：`oma check` 已绿（本机 Windows 已装 0.10.0）
- 非目标：
  - 本轮不实现完整 `oma spawn` / REPL / 网页 HTTP
  - 不先上四路真实 agent（布局/drive 用 pwsh echo 桩）
  - 不 `kill-server`、不默认弹浏览器、不抄 CreateOrReuse 叠窗格

## 风险与回滚

- Job Object `os error 5`：记 MISTAKES；POC 用 WMI 在 job 外拉起 daemon 再 `connect()`，不当默认 kill-server，不把 wt 当默认
- paste 协议构造失败：退 CLI `paste-buffer -p`
- 回滚：删 example 会话名；不碰用户其它 rmux 会话

## 验收标准

- 每个待办部件有 `examples/poc-*.rs` 且本机 `cargo run --example …` 退出 0。pane 最小集（endpoint/session/layout/drive/dialogs/paste）已在 Windows 验收；Linux/mac 委托后续仓库
- 负例不作为「成功路径」合入 `src/`
- `oma check` 仍绿；POC 不调用 `kill-server`
- 清单、GOAL/TODO/PLAN 与磁盘一致
- 完成后在 `docs\diary\` 补一笔；方案回填「实施过程与经验」

## 实施过程与经验

### paste（2026-08-31，Windows 绿）

- 原设想「SDK 协议建会话 + CLI paste」混合路线不成立。0.10.0 源码核实：`RmuxCommandKind::Request` 是惰性 DTO，`Pane::transport()` 是 `pub(crate)`，外部无裸 Request 发送口；`Rmux::cmd()` 在 Windows 注入 `-S <pipe>`，而 CLI 对一切 `-S` 形态无条件拒绝（含 `\\.\pipe\rmux-...` 前缀、裸名、SID 派生全名）。[实证: 2026-08-31]
- 实际路线为全 CLI：`-L <pid+tag label>` 专用端点。label 的 daemon pipe 名是 `\\.\pipe\rmux-S-<SID>-il-medium-<label>`（label 明文后缀）；client 报错里出现的 `g-<hash>-<salt>` 形是回落的哈希名，不是 label 正名。[实证: 2026-08-31 列 pipe 对比]
- Job Object 下 WMI 起 daemon 的启动命令必须是 `new-session -d` 而非 `start-server`：空 server 会因 exit-empty 立即退出。WMI 返回早于 daemon 绑 pipe，首条本地命令前要轮询 `list-sessions` 等 ready。[实证: 2026-08-31]
- 三段式验证达成：payload 文件（UTF-8 中文、无换行、无 ESC）经 `load-buffer -b` + `paste-buffer -p -b -t session:0.0` 粘入，Enter 单独 `send-keys`，`capture-pane -p` 轮询到执行输出行。marker 用拼接式（`('奥' + '马粘贴成功')`）区分回显行与执行行，防「回显命中」假阳性。[经验: evo-harness driver 同款三段式，本仓首次在 Windows 实跑中文]
- 收尾只 `kill-session` + `delete-buffer`；label daemon 随末 session 自动退出（exit-empty），无需 kill-server。临时 payload 文件删除。
