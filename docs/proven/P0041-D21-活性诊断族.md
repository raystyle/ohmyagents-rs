# D21 oma diagnose 活性诊断族

- 状态：已完成（131 单元加 21 集成全绿；四门禁绿；真网关实收）
- 日期：2026-09-09
- 关联：PRD D21；ohmyagents-rs#8（ohmycloud D45 配套需求单）；ohmycloud D45 缓存矩阵与 thinking 阶梯实测；D20 口径（凭据只读不建存储）

## 背景与问题

ohmycloud D45 把各 agent token 配置接管到统一网关（私有 API 域名，配置注入，2026-09-13 按 D31 清扫后仓面不再落明文；16 别名 8v8），跨仓发来 ohmyagents-rs#8：缓存测试与 agent 配置检测进 oma 诊断功能。用户裁独立 `oma diagnose` 族与 doctor 分家（doctor 保持零网络零 token 只读体检；diagnose 打真 API 烧最小 token）。ds 缓存结论经用户科普修正：官方 anthropic 端点走全自动前缀匹配（64 token 重合自动命中加优惠计费），usage 不透传字段，矩阵为 15 显式加 1 隐式，全 16 模型实际都有缓存能力；codex 默认别名换 zy-gpt56sol-codex（astra 上游无缓存透传让位）。

## 方案

- **网关发现三源**：`OMA_GATEWAY_URL`/`OMA_GATEWAY_KEY` env 覆盖 > claude `~/.claude/settings.json` env（ANTHROPIC_BASE_URL 加 AUTH_TOKEN）> codex `~/.codex/config.toml` 激活 provider base_url（剥 /v1 尾）加 auth.json OPENAI_API_KEY。凭据只读 agent 侧原生配置（D45 模板下发形态），不新建存储。
- **diagnose cache**：别名缺省 = GET /v1/models 全量；线判 `-codex` 尾走 /v1/responses、其余走 /v1/messages。同 payload 双连（至多三连取优）：claude 线 system 带 `cache_control: ephemeral` 约 2000 token 长文本读 cache_creation/read_input_tokens；codex 线 instructions 读 `usage.input_tokens_details.cached_tokens` 与 cache_write_tokens。verdict 五态：hit / write-only / auto-prefix（ds claude 线特判）/ none / error；任一 error 退出 1。
- **diagnose agents**：claude base_url 指向态、ANTHROPIC_MODEL 加 DEFAULT 三键在册核对、MAX_THINKING_TOKENS 对实测上限表（zy-claudefable5 与 zy-claudeopus48 = 65536，未知报 info）；codex provider 指向、model 在册、auth.json key 单独一发 /v1/models 判活性。

## 落地与验收

- `src\diagnose.rs`（约 470 行含测试）加 main.rs 接线；131 单元加 21 集成全绿（新增 7 件：线判、verdict 各态含 ds 特判与三连取优、caps 表、长文本确定性、渲染 error 面）。
- 真网关实收 [实证： 2026-09-09]：codex 线 zy-gpt56sol-codex 双连 cached_tokens 1792（hit）；claude 线 zy-claudefable5 显式写入 1927（网关两连异区只写不读形态，催生三连取优设计）；ds 线 ds-deepseekv4pro-claude auto-prefix（与矩阵一致）；diagnose agents 在本机（未 D45 渲染）如实报 missing 与 warn-not-gateway 与 warn-not-on-record 全套防漂移判据；WSL 床交叉验证 zy-codex 全通。
- 别名真名以 /v1/models 为准（ds 线实名 ds-deepseekv4pro-claude 等，手猜短名会被网关 502 unknown provider 拒）。

## 坑与处理

1. 缓存门槛差一：40 块 filler = 1005 token，差 1 过 1024 门槛全部不命中；96 块约 2000 token 后 codex 线即出 cached 1792 [实证： 两轮对照]。
2. 网关异区只写不读：claude 线两连 geo 不同（not_available 与 global）、input 差 24 token，第二连重新 created 而非 read；处置 = 三连取优（读到即停），持续只写判 write-only 不误报 none [实证]。
3. 上游路由瞬断：Windows 本机到 zy 上游 10060 与 502 混发（ohmycloud 同期 360 拥塞余波），WSL 同命令全通；error verdict 带原因如实上报即产品语义。
4. M054 五犯：heredoc python 反斜杠路径又被 JSON 吃层（`\v` 动词符劈断锚点）。处置升格：含反斜杠的文本批改一律 Edit / Write，heredoc 只做无反斜杠内容。

## 经验

- 活性诊断的 verdict 设计要押「证据分级」而非二值：hit（读到）最强、write-only（显式写入但读未落地）次之、auto-prefix（机制在但不可见）要靠领域知识特判、none（真无）与 error（打不通）分开；网关类探测一值多因，二值 verdict 必然误报 [实证： claude 线异区形态]。
