# D18 状态栏用户级定制

- 状态：已完成（145 单元加 24 集成全绿；本机部署实跑与四家 verify 全绿）
- 日期：2026-09-09
- 关联：PRD D18；S025（四家状态栏矩阵）；M045（codex 无外部命令面）；M046 / M048（Grok ASCII 与 .cmd 单路径）；R011（kv 只增）；M054

## 背景与问题

用户问「能定制状态栏么」。现状是 `oma-statusline.ps1` 唯一权威在 oma 二进制内嵌 `STATUSLINE_PS1` 整体 const，每次 `oma agents statusline` 整文件重释放，手改落盘必被重盖，定制能力只能在 oma 生成时做。第 2 轮三裁（2026-09-09）：定制粒度三层全要（段落开关加整脚本替换加模板变量）、合并语义 = 键级缺省回落内嵌默认（`segments` 清单写下即全量序）、codex 一并支持（内置项 ID 子集）。

## 方案

生成时烘焙（不是运行时读配置）：oma 每次运行读 `~/.oma/statusline.toml`，按配置拼装定制脚本后落盘。键级缺省回落：没写的键用内嵌默认，坏文件硬错退出 1（错误带文件出处）。

- **拆段拼装**：单体 const 拆 HEAD（param / UTF-8 / JSON 解析 / 助手）、COMMON（目录与仓库根）、PROBE（projKind 探测）、14 个段块、TAIL；`assemble_statusline_ps1(order, cfg)` 按序重组。COMMON 与 PROBE 按消费方门控（无 dir / oma 不跑 rev-parse；无 package 与工具链段不跑探测，省 kimi 300ms 预算）。
- **三层键**：`segments`（未知与重复 id 硬错）、`[template]`（占位符替换，`<段>-ascii` 给 grok 结构差异）、`[icons]`（键级回落，oma 宽字形默认两空格）、`[codex] items`（原样透传，未知 id codex 侧静默跳过）。
- **整脚本替换**：`--script <路径>` 拷自备脚本到部署位加 `.custom` marker（重跑跳过内嵌覆盖），`--builtin` 还原；调用契约：首参 agent 名、stdin 喂 agent JSON、stdout 单行、kimi 300ms。
- **防注入**：模板与图标值经单引号加倍转义烘焙进 ps1 字面量，用户串无法越出（多行值同样惰性）。

## 落地与验收

- `src\statusline.rs`：拼装器、配置解析、烘焙块、段块模板化改写、marker 语义；`src\main.rs`：`--example` / `--script` / `--builtin` 旗标与 kv 面（`statusline.custom` / `statusline.script` 只增）。
- 等价迁移双保险 [实证： 2026-09-09]：切片 1 与切片 3 各做一轮四路 mock（claude / grok × 空 / 全 JSON）pwsh 直跑，与拆段前基线输出逐字节一致；PROBE 前移为纯位置移动。
- 本机验收 [实证]：`oma agents statusline` 部署新烘焙脚本、部署脚本 mock 直跑渲染正常、`oma agents verify` 四家两层全绿。
- 测试 [实证]：单元 141 升 145、集成 21 升 24（拼装器序与门控、配置解析与未知键硬错、烘焙合并与注入防逃逸、marker 存活与还原、codex 子集、`--example` 与旗标互斥）；四门禁绿。

## 坑与处理

1. 图标码位不能凭记忆写：预猜 package / rust / ts 三码位全错，python 实测抽取（F03D7 / F1617 / F06E6）才落 DEFAULT_ICONS [实证： 本轮抽取]。
2. pwsh 行为判据测试的封闭性：子进程必须摘 `OMA_AGENT` 与 `OHMYAGENTS_STATE_FILE`（宿主 agent 会话会盖掉传入的 agent 名）、cwd 钉 scratch（活仓 `.oma/state` 会泄漏状态，unknown 断言翻车） [实证： 两轮红后修绿]。
3. 经 Bash 工具传 python heredoc 的反斜杠序列被 JSON 编码吃一层，同会话同型连踩，记 M054；Rust 源内 `\u{...}` 常量改用 Edit 工具直改。
4. cargo fmt 1.9.0 与 D17 提交存量有换行风格漂移（七文件），按「一事一提交」单独 chore 清零。

## 经验

- 单体脚本定制化改造的等价判据链：边界插入式拆段（默认序拼装与原文只差块位置）加 mock 直跑字节比对加 verify 判据面复用，三层证据都绿才算等价 [实证： 本轮]。
- 生成时烘焙优于运行时读配置：保持「二进制是唯一权威」的产品前提，ps1 无需 toml 解析能力，坏配置在部署时硬错而非渲染时静默。
